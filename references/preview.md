# Interactive component gallery and documentation

For a full design-system deliverable produce a locally runnable preview page, conceptually similar to https://ui.shadcn.com/docs/components, adapting to the project's framework. Prefer rendering the actual exported components and real shared tokens, not screenshots or duplicate mock components. Include navigation/index, search where useful, component sections, descriptions, live examples, relevant variants, interaction states, usage/code examples, and token references. Show disabled, loading, error, empty and responsive examples where applicable. Support keyboard and touch, labels, visible focus, reduced motion, and long content. Link to documentation or design artifacts when present.

The bundled `assets/starter/index.html`, `styles.css`, `app.js`, and `tokens.json` form a zero-dependency, browser-openable neutral example with navigation, search, theme switching, live button, form, tabs and dialog. It demonstrates the format but is not a production component library and does not automatically render a project's components. Replace examples with real components and tokens when implementing. Avoid presenting fake previews as tested production behavior.

Validate by opening the actual preview and exercising its controls. Inspect wide/narrow widths, focus, search, navigation, modal closure/return, theme and reduced motion. If a browser is unavailable, state that limitation; static checks are not visual verification. If the task is only an audit, describe a gallery recommendation instead of silently expanding scope.
