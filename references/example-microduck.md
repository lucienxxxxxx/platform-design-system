# Worked example: robot platform

Illustration only: these are possible directions, not measurements or verified behavior from the official site. Start from actual URLs, source and brand assets, and log evidence. A marketing page, simulator and device console have different density requirements while sharing foundations.

Possible principles: approachable and technically credible; expressive for discovery, calm for operation; feedback reflects real device state; essential interaction never depends on hover. Candidate pilot: product page plus device status panel. Candidate components: button, dialog, tabs, robot card, color selector, status and action preview. Define device command idle → sending → acknowledged/running → completed or failed/offline, timeout and stop/cancel when supported. Do not imply command success from animation.

Tokens and motion remain hypotheses until verified. Test long names, keyboard selection, touch, disconnected state and reduced motion. Record source, viewport and unobserved states. Product marks, photos, models and video require appropriate rights; the neutral starter contains none.
